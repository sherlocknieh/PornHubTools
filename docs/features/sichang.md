# 思畅 AI：朗读音频捕获

## 行为

- 页面：`https://sichang.xyz/*` 聊天页。
- 点消息下方的「朗读」后，脚本在 `POST /api/tts` 的响应旁克隆一份音频流，封装成 WAV，列在右下角「语音捕获」面板里。
- 响应一到就先占一行并显示「捕获中」；流结束后补齐时长，播放与下载按钮才可用。
- 进度条：捕获中是不确定进度动画（流没有总长度）；播放时变成真实播放进度，点击可跳转。
- 每条记录可播放/暂停、下载 `.wav`、删除；只保留最近 20 条，被挤掉或删除的记录会释放 blob URL。
- 面板只在捕获到音频后出现条目，空状态给一行提示；右上角「−」折叠，「清空」一次移除全部。

## 接口契约

| 项 | 值 |
| --- | --- |
| 请求 | `POST /api/tts`，JSON `{text, voice, rate, format}`，`format` 当前为 `"pcm16"` |
| 响应 | `content-type: audio/pcm`，**流式**裸 PCM16，单声道 |
| 采样率 | 响应头 `X-Sample-Rate`（实测 `24000`），缺失时按 24000 处理 |

站点改版时先看 Network 里的 `/api/tts`：接口路径、采样率头或音频格式任一变化，都会表现为「面板一直空着」，此时改 `src/handlers/sichang.js` 顶部的常量与封装逻辑。

## 边界

- 页面中途停止朗读会取消流；已读到的部分照常保存成一条较短的记录。
- 单条上限 64 MB（约 22 分钟），超出后继续把流读完但不保存新数据，避免克隆分支在内存里堆积。
- 只在宿主页面脚本可用的环境下工作（`@grant none` 直接注入页面世界）。
